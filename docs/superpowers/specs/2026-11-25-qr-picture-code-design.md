## 1. 코드를 읽고 새로 알게 된 것

### 1.1 그림 코드는 '이미 있는 그룹 방'에서만 열린다

- 위치: `backend/src/handlers/codeHandlers.ts`의 `code:open`
  - `roomId`가 그룹 방(`prv-g-…`)이어야 한다.
  - 열려는 소켓이 그 방의 멤버여야 한다.
  - 조건이 안 맞으면 `NOT_ALLOWED`를 돌려준다.
- 그래서 혼자인 화면의 PC는 그대로는 코드를 열 수 없다. 이 PC는 그룹 방이 없기 때문이다.

방법은 두 가지다.

| 방법 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A1 (추천)** 숨은 방을 미리 만든다 | 혼자인 화면이 뜨면 `private:create`로 그룹 방을 만들고, 그 방으로 `code:open` | 서버 수정이 없다. 백엔드를 손으로 배포하느라 늦어지는 문제가 없다 | 혼자인 PC마다 서버 메모리에 방이 1개 생긴다. 방 한도(`MAX_PRIVATE_ROOMS_PER_SOCKET`)를 1칸 쓴다 |
| A2 서버에 '방 없는 코드'를 더한다 | `code:open {route}`를 roomId 없이 허용한다. 승인할 때 방을 만든다 | 쓰지 않는 방이 생기지 않는다 | 서버 수정과 백엔드 배포가 필요하다. 프런트에 예전 서버용 대비책도 있어야 한다 |

A1의 숨은 방은 이렇게 다룬다.
- 승인 전에는 방 목록(`privateRooms`)에 넣지 않는다. 방 비밀, 입장권, roomId는 메모리에만 둔다. 그래서 화면에도 저장소에도 남지 않는다.
- 혼자 상태가 끝나거나, 탭을 숨긴 지 30초가 지나거나, 같은 네트워크로 연결되면 `code:close`를 보내고 `private:leave`로 나간다. 빈 방은 지금처럼 서버가 정리한다.
- 승인되면 그때 `privateRooms.addRoom`으로 목록에 넣고 방 탭으로 전환한다. 이름은 기존 `group.defaultName`을 쓴다.
- 방을 만들 수 없으면(`TOO_MANY_ROOMS` 등) 코드 없이 지금의 고정 QR을 보여 준다.

### 1.2 `#` 뒤의 값이 GA4로 새는 경로가 있다

- 위치: `frontend/index.html`
  - `gtag('config', …, { page_location: location.href })`
  - `location.href`에는 `#` 뒤도 들어간다.
- 그래서 명세의 `#pc=…&c=…`를 앱 코드(`main.js` 이후)에서 지우면, GA4의 `page_location`에 그림 코드가 실린다.
- 이미 쓰는 방식이 있다. `#/send?`(텍스트 미리 채우기)와 `#/pv?`(그룹 초대)는 `index.html`의 인라인 스크립트가 GA보다 먼저 값을 꺼내 `window.__cs…`에 옮기고 `history.replaceState`로 지운다.
- 이번에도 같은 방식으로 한다.
  - 형식: `#/qc?pc=…&s=…&c=…`
  - 값은 `window.__csQrCode`로 옮긴다.
  - 열린 탭에서 `#`만 바뀌는 경우는 `cs-qr-code` 이벤트로 앱에 알린다.
- QR 주소 예: `https://www.clipboardapp.org/?utm_source=qr&utm_medium=empty_state#/qc?pc=3-17-0&s=Xy9…&c=0a0f1203`
  - `utm_*`는 그대로 둔다. 그래서 `qr_arrive` 측정이 계속된다.

### 1.3 서버 쪽 확인 결과 (명세 6.4의 질문)

| 질문 | 결과 (근거) | 대응 |
|---|---|---|
| 혼자인 동안 코드를 열어 두고 갱신해도 되나: 한도 | 전체 동시 활성 코드는 **500개**다(`MAX_ACTIVE_CODES`). 넘으면 `BUSY`. 소켓당 코드는 1개이고, 새로 열면 이전 것이 닫힌다 | 지금 동시 접속은 수십 명 수준이라 여유가 있다. 다만 혼자인 PC가 많아지면 실제 방의 그림 코드와 500칸을 나눠 쓴다. `BUSY`면 고정 QR로 돌아간다. 활성 수는 서버 로그의 '그림 코드 열림 (활성 N개)'로 본다 |
| 속도 제한 | `code:*`는 소켓당 토큰 버킷이다(용량 20, 초당 5). 갱신은 5분에 1번이다 | 문제없다 |
| 메모리 | 코드 1개는 route, 호스트 ID, 만료 시각만 갖는다. 세션은 90초 뒤 정리된다(1초마다 정리) | 문제없다. 숨은 방(A1)이 메모리를 더 쓰지만 방 1개 크기 수준이다 |
| 화면을 보지 않는 PC가 세션을 오래 붙잡나 | 서버는 소켓이 끊길 때만 코드를 지운다. 탭만 열어 둔 PC는 5분마다 갱신하며 계속 붙잡는다 | **G**: 탭이 보일 때만 연다. 숨긴 지 30초가 지나면 닫는다. 다시 보이면 새로 연다 |
| 실패 제한 | 틀린 코드는 소켓당 5회, IP당 30회에서 3분간 잠긴다 | QR은 자동 입력이라 틀릴 일이 거의 없다. 교실 IP 한도(30회)에도 영향이 없다 |
| 호스트당 세션 | 동시 20개(`MAX_SESSIONS_PER_HOST`) | D(1대)와 함께, 첫 승인 뒤에는 코드를 바꿔 다른 사람이 들어오지 못하게 한다 |

**서버 수정은 없다.** 단, A2를 고르면 서버 수정이 필요하다.

## 2. 흐름

### 2.1 PC (혼자인 화면)

1. 다음 조건이 모두 맞으면 시작한다.
   - `ConnectionCard`의 혼자인 화면이 보인다(`showEmpty`).
   - 탭이 보인다(`visibilityState === 'visible'`).
   - 기기가 휴대폰이 아니다.
     - 휴대폰끼리는 QR을 찍기 어렵다. 2주 측정 뒤 넓힐지 정한다.
2. `private:create`로 숨은 방을 만든다(1.1).
3. `createCodeHost({ roomId, … })`를 시작한다(기존 `services/codeJoin.js`).
   - 그림 4개를 뽑고 `code:open`을 보낸다.
4. QR을 새 주소로 다시 그린다.
   - 코드를 받기 전과 실패했을 때는 지금의 고정 QR을 그린다. 화면이 비지 않게 하기 위해서다.
5. 5분마다 코드를 갱신하고, 갱신할 때마다 QR도 다시 그린다. 기존 `scheduleRenew`를 쓴다.
6. 다음 중 하나가 생기면 정리한다(`code:close`, `private:leave`).
   - 다른 기기가 들어와 혼자 상태가 끝났다.
   - 탭을 숨긴 지 30초가 지났다.
   - 페이지를 떠났다.

### 2.2 휴대폰 (QR로 도착)

1. `index.html`이 `#/qc?…`를 꺼내고 주소에서 지운다(1.2).
2. 앱이 소켓에 연결된 뒤 **4초** 동안 같은 네트워크 기기 목록에서 PC를 찾는다.
   - `presenceKey === pc` 또는 `socketId === s`인 기기를 찾는다.
3. **찾으면** 아무것도 하지 않는다. 지금과 같다.
   - 결과는 `qr_code_fallback {result:'same_network'}`로 기록한다.
4. **못 찾으면** `createCodeJoiner().join(그림 4개)`로 자동 입장을 시작한다.
   - 화면에 한 줄을 보여 준다: "다른 네트워크라서 방으로 연결할게요"
   - 그 아래에 기존 대기 문구를 보여 준다: "방 쪽에서 들여보내 주기를 기다리고 있어요"
5. **성공하면** 기존 그림 코드 입장처럼 방을 추가하고 방 탭으로 전환한다.

### 2.3 PC (승인)

1. 기존 승인 카드를 띄운다(`PictureCodeShow`의 요청 카드와 같은 내용).
   - 문구: "{이름}가 들어오려고 해요" [들이기] [거절]
2. 카드 위치
   - 혼자인 화면의 QR 바로 아래에 띄운다.
   - 확인하는 대상(QR)과 그 동작(들이기)을 떨어뜨리지 않기 위해서다(owner 화면 원칙 3).
3. **들이기를 누르면**
   - 숨은 방을 `privateRooms`에 추가하고 방 탭으로 전환한다.
   - 바로 새 코드로 바꾼다(D).
   - 방이 생겼으므로 그다음 QR은 이 방의 초대가 아니라 다시 혼자인 화면 규칙을 따른다.
4. **거절하면** 새 코드로 바꾼다. 거절한 사진이 다시 쓰이지 않게 하기 위해서다.

### 2.4 실패 처리

- 대상: 만료, 거절, 시간 초과, 그리고 기존 `wrong`, `busy`, `wait`
- 휴대폰에는 기존 `code.*` 오류 문구를 보여 주고, 그 아래에 새 문구를 붙인다: "PC 화면의 새 QR을 다시 찍어 주세요"

## 3. 측정

| 이벤트 | 매개변수 | 상한 |
|---|---|---|
| `qr_code_fallback` (새로 만듦) | `result: same_network \| room_ok \| declined \| expired \| timeout \| error` | QR 도착 세션당 1회(sessionStorage) |
| 기존 `connected_any {way}` | `ip_first`, `ip_existing`, `room` | 바꾸지 않는다 |
| 기존 `code_show`, `code_renew`, `code_request` | 그대로 | 혼자인 화면에서는 `code_show`를 보내지 않는다. 기존 방 초대 측정과 섞이지 않게 하기 위해서다. `code_renew`는 5분마다 생기므로 이 경로에서는 끈다 |

- 그림 인덱스, 이름표 키, 소켓 ID, roomId는 어떤 이벤트에도 넣지 않는다.
- **GA4 등록 필요**: 이벤트 `qr_code_fallback`의 매개변수 `result`. 이미 다른 이벤트에서 `result`로 등록되어 있다면 그대로 쓴다.

## 5. 위험과 남은 질문

1. **교실 화면처럼 QR이 여러 사람에게 보일 때**
   - 코드 1회 사용(D)과 PC 승인(F)으로 막는다.
   - 다만 먼저 찍은 사람의 요청이 승인 카드에 먼저 뜬다.
   - 같은 와이파이의 학생은 3번 단계(같은 네트워크에서 PC를 찾음)에서 끝나므로 코드를 쓰지 않는다.
2. **휴대폰은 같은 와이파이인데 PC가 4초 안에 목록에 안 보일 때**
   - 이 경우 휴대폰이 방으로 넘어간다.
   - 결과는 그래도 연결이고, 방과 같은 네트워크 두 탭에 모두 PC가 보인다.
   - 목표 비율(5% 이하)은 `qr_code_fallback` 대비 `connected_any` 숫자로 본다.
3. **이름표 다시 뽑기**
   - PC가 기다리는 4초 안에 이름표를 다시 뽑으면 키가 바뀐다.
   - 그래서 소켓 ID도 함께 넣었다(`s`). 둘 다 안 맞으면 방으로 넘어간다.
4. **실제로 다른 네트워크에서 확인하기**
   - 데스크톱 브라우저 두 개로는 다른 네트워크를 만들기 어렵다.
   - 단위 테스트와 로컬 서버 두 탭으로 흐름을 확인한다.
   - 실제 확인은 사람이 휴대폰 데이터로 해야 한다.
5. **배포 순서**
   - A1은 프런트만 배포하면 된다.
   - A2를 고르면 백엔드를 먼저 배포해야 한다. 지금 백엔드는 손으로 배포한다.
