## 0. 왜 이 순서인가 (2026-11-13 조사)
- 한국어 "종단간 암호화" 자동완성은 뜻·해제·인스타·메신저뿐이다(파일 전송 의도 아님). "암호화 파일 전송", "안전한 파일 전송"은 네이버·구글 자동완성 없음. 구글 "파일 암호화 사이트"는 있다.
- 지난 잠금 가이드 0014("파일 비밀번호 걸어서 보내기")는 28일 구글 노출 4·클릭 0, 네이버 노출 114·클릭 0으로 rejected(11-13).
- 영어 자동완성은 있다: "end to end encrypted file transfer", "e2ee file transfer", "secure online clipboard", "send password securely online", "encrypted pastebin".
- 그래서: 한국어는 **상황 검색 페이지에 차별점으로** 넣고, "종단간 암호화" 자체를 노리는 한국어 새 페이지는 만들지 않는다. 새 URL은 영어 1개만. 가장 기대하는 곳은 개발자 글(SPAKE2)과 영어 페이지.
- 자동완성은 검색량이 아니다. 판독 수치로 다시 판단한다(4절).

## 1. 제품 사실 (코드 기준 2026-11-14, master ab38740). 쓰기 전에 다시 확인한다
**암호화되는 것 (방)**
- "방" = 기기 목록의 "방으로 연결"로 만든 방, "＋ 방 → 새 방 만들기"로 만든 방, QR·링크·그림 코드로 들어간 방. 탭에 방 이름이 보인다.
- 방에 올린 파일은 **파일 이름과 내용이 이 기기에서** 방 열쇠로 암호화된 뒤 올라간다(`App.vue` 업로드: 방이면 `privateRooms.lockFor` → `lockedUpload`, `lockCrypto.encryptName`). 일반(공개) 업로드 경로는 쓰지 않는다.
- 방 텍스트도 방 열쇠로 암호화해 보내고, 서버는 암호문만 10분 보관한다(`useTextQueue`, `privateText.js`).
- 방 열쇠(32바이트 비밀)는 서버로 가지 않는다.
  - 기기 목록 연결: ECDH P-256 1회용 키로 감싸서 넘기고, 두 화면의 그림 4개로 가운데 가로채기를 확인한다(`pairCrypto.js`).
  - QR·초대 링크: 열쇠는 주소의 `#` 뒤에 있어 서버 요청에 실리지 않고, 앱이 분석 도구보다 먼저 주소창에서 지운다(`index.html`).
  - 그림 코드: 그림 4개를 비밀번호로 쓰는 SPAKE2(RFC 9382, P-256, `@noble/curves`)로 열쇠를 넘긴다. 서버는 어느 방인지 찾는 앞 2개 그림만 안다. 방 쪽에서 "들이기"를 눌러야 들어온다. RFC 부록 B 시험값 재현 테스트가 있다.

**서버가 보는 것 (숨기지 않는다)**
- 파일 크기, 올린 시각, 기기 이름표(동물·기기·브라우저), 어느 기기가 어느 방에 있는지, 접속 IP.

**암호화되지 않는 것**
- 기본 탭 "같은 네트워크"와 "전체 공유"는 잠그지 않으면 파일·텍스트가 평문이다. 그 탭에서는 "비밀번호로 잠그기"를 켜야 브라우저에서 암호화된다(PBKDF2 → AES-GCM, `lock-campaign.md` 1절).

**한계 (개발자 글·FAQ에 솔직하게)**
- 웹앱이라 사이트가 내려주는 코드를 믿어야 한다(설치형 앱의 E2EE와 다른 점). 코드는 MIT 공개(GitHub).
- 초대 QR·링크는 10분 동안 가진 사람 누구나 쓸 수 있다(받는 쪽에 입장 확인 창이 뜬다). 들어온 기기를 내보내는 기능은 아직 없다.
- 방 파일은 올린 지 약 1일 뒤 지워진다(방은 30일 유지). 텍스트는 10분.
- 브라우저 데이터를 지우면 방 열쇠도 사라져 그 방에 다시 못 들어간다.

## 2. 문구 규칙
쓸 수 있는 핵심 문장(채널 톤에 맞게 다시 쓴다. 복붙 금지):
- 한국어: "방에서 주고받은 파일과 텍스트는 파일 이름까지 내 기기에서 암호화돼요. 방 열쇠는 서버로 가지 않아요."
- 영어: "Files and text you share inside a room are encrypted on your device, file names included. The room key never goes to the server."
- "종단간 암호화(end-to-end encryption)"라는 말은 **반드시 "방에서"/"inside a room" 같은 범위와 함께** 쓴다.
쓰지 말 것 (`ops/content-rules.json`이 막는 것 포함):
- 범위 없는 "모든 파일/데이터 종단간", "기본으로 종단간", "end-to-end encrypted by default", "everything is end-to-end".
- "운영자도 볼 수 없", "zero-knowledge", "완벽한 보안", "해킹 불가", "최초·유일".
- 기기 정보·파일 크기까지 숨겨진다는 서술. 같은 네트워크 탭이 암호화된다는 서술.
- 악용 프레이밍: "몰래", "추적 불가", "익명 전달", "검사 피하기".
- 경쟁 서비스 비교는 공식 문서로 확인한 것만, 확인 날짜를 적는다. 비하 금지.
