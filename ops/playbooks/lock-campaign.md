# 비밀번호 잠금 캠페인 (2026-10-16 ~ 2026-11-15)

owner 지시(2026-10-15): 새로 나온 비밀번호 잠금·QR 공유를 유입 각도로 써서 사용자를 더 모은다.
기존 daily-loop의 요일 구성은 그대로 두고, 이 기간에는 아래 순서로 **잠금 소재를 먼저** 쓴다.
매 실행마다 이 파일을 읽는다. goal.md 제약(스팸·과장·다계정 금지)이 이 문서보다 우선이다.

## 1. 제품 사실 (코드 기준 2026-10-15, master 5c40fc6 — PR #52~#55)
글·페이지에 쓰기 전에 라이브 사이트와 코드(`frontend/src/utils/lockCrypto.js`, `services/lockedUploader.js`, `services/lockedDownloader.js`, `components/LockedFileCard.vue`, `components/LockedLinkPage.vue`)로 다시 확인한다.
- 같은 네트워크·전체 공유 탭 모두 업로드 전에 "비밀번호로 잠그기"를 켤 수 있다(4자 이상). 전체 공유는 처음 보낼 때 뜨는 확인 창에도 선택 비밀번호 칸이 있다.
- 파일 이름과 내용을 **보내는 기기(브라우저)에서** 암호화한 뒤 올린다. 비밀번호 → PBKDF2-SHA256 60만 회 → AES-GCM, 파일마다 랜덤 키. 서버에는 암호문과 비밀번호 확인값만 간다. 비밀번호·키는 서버로 보내지 않는다.
- 받는 쪽은 같은 비밀번호를 입력하면 그 기기에서 풀어 저장한다. 틀린 횟수는 제한된다.
- QR 공유: 잠긴 파일 "…" → "QR 코드로 공유". 링크의 `#` 뒤에 그 파일 하나의 키가 들어가 서버 요청에는 실리지 않는다. QR을 가진 사람은 비밀번호 없이 받는다(QR 사진 관리는 사용자 책임). 내가 잠갔거나 이번 접속에서 비밀번호를 확인한 파일만 QR을 만들 수 있다.
- **잠기지 않는 것**: 텍스트, 기기 정보(동물 이름표·기기·브라우저), 파일 크기·보낸 시간. 잠긴 파일은 미리보기·썸네일·일괄 선택이 없다.
- 보관은 일반 파일과 같다(모두 나가면 곧 삭제, 최대 약 1일). 비밀번호를 잊으면 되찾을 방법이 없다.
- 실기기에서 아직 확인 안 된 것(아이폰 큰 파일 복호화 상한 등)은 숫자로 쓰지 않는다.

## 2. 메시지 규칙
핵심 문장 (채널 톤에 맞게 다시 쓴다. 복붙 금지):
- 한국어: "민감한 파일은 비밀번호로 잠가서 보내세요. 보내는 기기에서 암호화되어, 비밀번호를 아는 사람만 열 수 있어요."
- 영어: "Lock a file with a password before sending: it is encrypted in your browser, and only people with the password can open it."
- 차별점은 **조합**으로 말한다: 같은 와이파이면 가입 없이 자동 연결 + 받는 사람이 나중에 열어도 됨(최대 약 1일) + 필요한 파일만 잠금 + QR로 넘기기.

쓰지 말 것:
- "최초", "유일", "국내 최초", "완벽한 보안", "해킹 불가", "모든 데이터 암호화", "운영자도 열 수 없어요"(앱에서 뺀 표현).
- 텍스트·기기 정보까지 보호된다는 서술. 잠금이 기본값이라는 서술(직접 켜야 한다).
- "종단간 암호화"/"end-to-end encrypt"는 `ops/content-rules.json` 금지 문구다. owner가 PR #56(금지 문구 조정)을 머지하기 전에는 사이트·블로그·커뮤니티 어디에도 쓰지 않는다. (PR #56은 2026-10-15 머지됨 → 이제 쓸 수 있으나 아래 한정어 규칙 필수) 머지 후에도 "비밀번호로 잠근 파일은" 같은 한정어를 반드시 붙인다.
- 악용을 부르는 프레이밍: "검사 피하기", "몰래", "추적 불가", "익명 전달". (Firefox Send는 악성코드 배포에 악용돼 2020년에 종료됐다.)
- 경쟁 서비스 비교는 공식 문서로 확인한 사실만. 확인된 것(2026-10-15): PairDrop·Snapdrop은 WebRTC P2P라 두 기기가 동시에 켜져 있어야 함, Wormhole은 링크 `#`에 키를 넣는 E2E·24시간 보관, Firefox Send는 2020-09 종료(포크 send.vis.ee). 비하하지 않는다.

## 3. 대상과 키워드 (가설 — 측정으로 검증)
- 한국어: 공용 PC(PC방·학교·회사·도서관·프린트 카페)에서 신분증 사진·증명서·계약서·이력서를 옮기는 사람, 같은 와이파이를 여러 사람이 쓰는 곳. 후보 키워드: "파일 비밀번호 걸어서 보내기", "파일 암호화 전송", "신분증 사진 컴퓨터로 옮기기", "공용 PC 파일 전송", "QR코드로 파일 보내기".
- 영어: "Firefox Send alternative", "encrypted file sharing no sign up", "send a file with a password", "password protected file transfer free".
- 페이지를 만들기 전에 GSC·서치어드바이저에서 위 키워드 노출이 이미 있는지 보고, 있는 것을 먼저 고른다.

## 캡처 팁 (2026-10-16)
- 잠금 비밀번호 칸을 누르면 브라우저 비밀번호 관리자(Aside) 제안 팝업과 "Save credential" 창이 사이트 위에 겹친다. 캡처 직전에 페이지 안의 `#app` 밖 iframe을 `display:none`으로 숨기고, 저장 창은 Close로 닫는다(저장하지 않음).
- 받는 쪽 화면은 같은 브라우저의 새 탭으로 열면 된다(새 탭은 키가 없어 파일 이름이 문자열로 가려지고 "풀기"가 보임). 받는 쪽에서 실제로 풀면 다운로드가 생기니 캡처는 비밀번호 입력 시트까지만.
- 잠긴 파일의 "⋯" 메뉴는 "QR 코드로 공유"와 "삭제"뿐이다. 캡처 후 "⋯ → 삭제", 잠금 "해제", 언어를 바꿨으면 한국어로 되돌린다.
